# LocalDrop

Нативная передача оригинальных файлов и текста iPhone ↔ Windows по локальной сети. Windows: Rust / Win32 (native-windows-gui), один процесс, системный трей. iOS 16.2+: SwiftUI, Photos, URLSession и Live Activity. Без Electron, браузерного интерфейса, внешнего сервера или облачного посредника.

## Быстрый запуск

1. Скачайте артефакты **Windows EXE** и **iOS unsigned IPA** на вкладке GitHub Actions после успешных сборок. Распакуйте ZIP артефактов.
2. Запустите `localdrop.exe`. Разрешите входящие соединения в брандмауэре Windows **только для частной сети**. TCP-порт: 45831. Не открывайте порт на роутере.
3. Подпишите `LocalDrop-unsigned.ipa` собственным сертификатом/профилем и установите своим инструментом. Сертификат, ключ и пароль не нужны проекту или Actions. Установка зависит от действительности вашей подписи, профиля, разрешённых устройств и настроек iOS; наличие неподписанного IPA само по себе установку не обеспечивает. TestFlight и App Store не используются.
4. Подключите оба устройства к одной доверенной сети. В Windows выберите IPv4 адрес Wi-Fi/Ethernet. VPN, гостевая сеть, AP isolation и запрет локальной сети в iOS могут мешать соединению.
5. Сканируйте QR в приложении iPhone. Подтвердите запрос кнопкой «Разрешить» на компьютере в течение 60 секунд. При отсутствии камеры вставьте весь JSON-код из Windows в «Ручное подключение» и нажмите «Подключить».
6. Выбирайте несколько файлов/оригиналов или отправляйте текст. В обе стороны файлы проверяются по размеру и SHA-256 перед публикацией. Закрытие окна Windows оставляет программу в трее; нажатие значка открывает окно, «Выход» завершает процесс.

QR и ручной код содержат секрет приглашения: не публикуйте их. Сопряжение и сертификат сохраняются через DPAPI текущего пользователя Windows и Keychain на iPhone. После первого подтверждения приложение подключается автоматически при открытии и возвращении из фона. При смене IP используется Bonjour/mDNS только в LAN; найденный компьютер обязательно проходит проверку сохранённого TLS-отпечатка. Если multicast запрещён сетью, остаются сохранённый адрес и QR. Недоступное соединение повторяется с увеличением задержки до 60 секунд, пока iOS-приложение активно. Для отзыва доступа используйте «Забыть устройство» в Windows и «Отключить и забыть» на iPhone. Один доверенный телефон.

Windows запускается при входе текущего пользователя, сразу в трей. Это можно отключить флажком «Запускать вместе с Windows» на вкладке подключения. Для автозапуска сохраняется путь к EXE: не удаляйте и не перемещайте его после настройки. Служба Windows и права администратора не нужны. Автообнаружение mDNS работает в том же процессе; нет сканирования диапазона IP-адресов.

## Оригиналы и ограничения iOS

Выбор через Photos picker используется только для идентификаторов. Исходные байты читаются через `PHAssetResourceManager.requestData`: ресурсы `photo`, `video`, `pairedVideo`, `alternatePhoto`, `audio`, без UIImage, JPEG-конвертации, AVAssetExportSession и перекодирования. Live Photo передаётся отдельными исходными фото/видео; автоматическая сборка Live Photo на принимающем устройстве не реализована. Выбираются оригиналы, а не версии с пользовательскими правками. Наличие ресурса и его доступность определяются Photos; ограниченный доступ может потребовать изменения разрешений.

По умолчанию скачивание оригиналов из iCloud запрещено. Если оригинала нет локально, приложение сообщает ошибку; пользователь может отдельно разрешить загрузку. Этот подготовительный этап требует интернета и места на телефоне. То же относится к файлам облачных провайдеров в приложении «Файлы». Дальнейшая передача между устройствами идёт напрямую по LAN.

Полученные файлы находятся в «Файлы → На моём iPhone → LocalDrop», а также доступны через системное меню «Поделиться / сохранить». Поддерживаемые Photos форматы можно добавить кнопкой «В медиатеку». Исходный полученный файл в Documents остаётся неизменным; дальнейшее поведение медиатеки контролирует iOS. Копирование и вставка текста выполняются явно пользователем.

На экране блокировки и Dynamic Island (на поддерживаемых устройствах) Live Activity показывает ход текущей передачи. Пользователь может запретить Live Activities в настройках; передача от этого не зависит. Баннер не предоставляет фоновое время и не использует APNs/внешние серверы; устаревшие сведения помечаются как приостановленные. Для текущей операции приложение запрашивает ограниченное время `beginBackgroundTask`; если iOS его отзовёт, запросы отменяются и показывается причина. Время не гарантируется, сертификат подписи не снимает это ограничение. Постоянное фоновое ожидание новых файлов и автоматическая синхронизация буфера не реализованы. Пока приложение активно и передаёт данные, оно предотвращает автоматическую блокировку экрана; ручная блокировка разрешена.

После возвращения нажмите «Подключить», если соединение остановлено. Нет возобновления с произвольного байтового смещения: недоставленный файл повторяется целиком. Нажатие «Отменить» на iPhone разрывает его текущие запросы; чтобы удалить всю очередь Windows, нажмите «Отменить передачи» на компьютере. Подтверждённые файлы не удаляются. При самостоятельной подписи IPA подпишите также вложенное расширение `LocalDropActivity.appex`, затем основное приложение — это стандартное WidgetKit-расширение, включённое в IPA.

## Протокол и сохранение

HTTPS/TLS (Rustls на Windows, системный TLS на iOS) с самоподписанным сертификатом. iPhone принимает **только точный SHA-256 DER-сертификата из QR**, запрещает перенаправления. 256-битное случайное приглашение и отдельный 256-битный токен после явного разрешения на компьютере. Собственных шифров или алгоритмов согласования ключа нет. SHA-256 проверяет файл независимо от TLS; отпечаток сертификата обеспечивает доверие к соединению. Подробности: [docs/PROTOCOL.md](docs/PROTOCOL.md).

Windows сохраняет новые данные в **Документы → LocalDrop → Received**, используя системный путь Documents, в том числе при перенаправлении на другой диск. Старые загрузки остаются в `%LOCALAPPDATA%\LocalDrop\Received`. Имена очищаются, совпадения получают числовой префикс. Проверенные временные файлы публикуются атомарным hard link без перезаписи; нужен NTFS или другая файловая система с hard link. Временные файлы находятся в соседнем каталоге LocalDrop/Staging на том же диске и удаляются при отмене, ошибке или следующем запуске после аварии. Второй экземпляр блокируется эксклюзивным файлом.

Окно Windows разделено на вкладки «Передача», «Подключение» и «Журнал». Входящий текст автоматически копируется в буфер Windows; при занятом буфере остаётся кнопка повторного копирования. Сверху экрана появляется компактный индикатор поверх обычных окон, без перехвата фокуса: объём текущего файла и его номер в отправке. После завершения он плавно исчезает; в простое его таймер выключен. Live Photo учитывается как несколько оригинальных файлов. Эксклюзивный полноэкранный режим и защищённый рабочий стол могут перекрывать topmost-окна.

iOS 0.2.2, сборка 4, метка **F4** внутри приложения: отдельный UIKit-контроллер открывает системный выбор файлов без предварительного копирования провайдером. После выбора явно закрывает окно, а доступ к security-scoped URL удерживается до завершения подготовки. Затем отправка начинается после закрытия SwiftUI-оболочки. Выбранные имена видны в приложении. Отправка не ждёт завершения долгого запроса приёма: для неё создаётся отдельная сессия. Иконки включены также отдельными PNG с явными CFBundleIcons, чтобы поддержать стороннюю переподпись. Windows EXE и трей используют такую же иконку. Генераторы: scripts/generate-ios-icon.ps1 и scripts/generate-platform-icons.ps1. В iOS workflow есть тест отправки и отдельный UI-тест нажатия «Открыть» в системном picker.

Для отправки Windows делает потоковую дисковую копию и считает хеш; это защищает передачу от изменения исходного файла после подготовки. Нужна дополнительная ёмкость диска размером с очередь. Максимум 128 элементов очереди, текст до 1 МиБ. Передачи файлов сериализованы. Оперативная память не растёт пропорционально размеру файла; буферы приложения 64 КиБ плюс буферы TLS/HTTP/ОС. Конкретный расход ресурсов требует измерений.

## Сборка

Windows: Rust stable, Visual Studio Build Tools с C++ и Windows SDK. MSVC release собирается со статическим CRT: отдельный установщик Visual C++ Runtime для запуска EXE не требуется. Системные DLL Windows остаются системными зависимостями.

```powershell
cargo test --workspace --locked
cargo build --release --locked -p localdrop
```

macOS: Xcode с установленной iOS SDK, XcodeGen (`brew install xcodegen`).

```sh
cd ios && xcodegen generate && cd ..
xcodebuild -project ios/LocalDrop.xcodeproj -scheme LocalDrop -configuration Release \
  -sdk iphoneos -destination 'generic/platform=iOS' -derivedDataPath build/DerivedData \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY='' build
mkdir -p build/package/Payload
cp -R build/DerivedData/Build/Products/Release-iphoneos/LocalDrop.app build/package/Payload/
(cd build/package && zip -qry ../LocalDrop-unsigned.ipa Payload)
```

Два независимых workflow запускаются на `push` и вручную (`workflow_dispatch`); артефакты хранятся 30 дней. Подпись не выполняется и секреты Apple не используются.

## Проверка на устройствах и измерения

Сценарии и инструкция измерения CPU/RAM: [docs/VALIDATION.md](docs/VALIDATION.md). Автоматические Windows- и iOS-сборки настроены и проверяются в [GitHub Actions](https://github.com/martynovkirill88-star/Wifi-/actions). Rust-тесты проверяют авторизацию, подтверждение сопряжения, целостность, обрыв, отмену, конфликты и очистку временных файлов. Проверка на настоящем iPhone, подпись/установка, Live Activity и измерения ресурсов остаются отдельными обязательными этапами. Нельзя считать успешную сборку достаточной проверкой поведения Photos, TLS и ограничений iOS.

Проверенные ссылки API: [Apple: оригиналы и доступ к сети](https://developer.apple.com/documentation/photos/phassetresourcerequestoptions/isnetworkaccessallowed), [Apple: download task пишет во временный файл](https://developer.apple.com/documentation/foundation/urlsessiondownloadtask), [Rust: уведомления UI из потока](https://docs.rs/native-windows-gui/latest/native_windows_gui/struct.NoticeSender.html).
